# Getting Started with AI

A short introduction for people who are new to AI tools at work. It explains what the tools do, what to use them for, and how to complete a first task safely.

## What is AI?

Artificial Intelligence systems help users generate content, analyse information, automate tasks, and support decision making.

The AI tools most people use at work are assistants that you talk to in plain language. You type a request, called a prompt, and the tool writes a response. You can then ask it to change, shorten or improve what it produced, as you would with a colleague.

These tools work by predicting useful text based on patterns in the material they were trained on. They do not look answers up in a database of facts, which is why they are fluent and fast, and also why they can be wrong.

## What AI Is Good At, and Where to Take Care

| Good at | Take care with |
| --- | --- |
| Producing a first draft quickly | Facts, figures, dates and references, which can be wrong or invented |
| Summarising long documents | Recent events, which the tool may not know about |
| Rewording text for a different audience or tone | Calculations, which should be checked |
| Suggesting ideas and options | Specialist legal, financial, medical or safety advice |
| Explaining an unfamiliar topic in plain language | Anything involving confidential or personal information |
| Turning notes into a structured format | Decisions about people, which need human judgement |

Think of the tool as a capable assistant who works quickly, never tires, and sometimes gets things confidently wrong. You stay responsible for the result.

## Common Use Cases

| Use case | Example prompt |
| --- | --- |
| Drafting emails | "Write a polite email asking a supplier for an update on a late delivery. Keep it under 100 words." |
| Research assistance | "Explain the main differences between two approaches to [topic], in plain English, for someone new to the subject." |
| Document summarisation | "Summarise the text below in five bullet points for a manager who has two minutes to read it." |
| Knowledge management | "Turn these rough notes into a step-by-step guide with numbered steps." |
| Process automation | "Write an Excel formula that shows 'Overdue' when the date in column B is more than 30 days ago." |
| Report generation | "Turn these figures into a short monthly summary with three key points and one recommendation." |

## Your First Task: A Worked Example

Choose something low-risk that you already know how to do, so that you can judge the result. This example drafts an email to move a meeting.

**1. Write a clear prompt**

> Write a short, friendly email to my project team. I need to move Thursday's 2pm planning meeting to Friday at 10am because of a clash. Ask them to reply if Friday does not work. Keep it under 80 words.

**2. Read the response properly**

Check that the days and times are right and that nothing has been added that you did not ask for.

**3. Ask for changes**

You do not need to start again. Follow up with an instruction:

> Make it slightly more formal and add a subject line.

**4. Check it and make it yours**

Correct anything that is wrong, adjust the wording so that it sounds like you, and then send it yourself.

That is the whole pattern: ask, read, refine, check.

## First Steps

1. **Start with simple tasks.** Pick everyday jobs such as drafting, summarising and rewording, where a mistake is easy to spot and costs little.
2. **Learn prompt writing techniques.** A clear request gets a better answer. See [Prompt Engineering Basics](PromptEngineeringBasics.md).
3. **Verify outputs.** Check facts, figures and names before you rely on them or share them.
4. **Experiment with different approaches.** Try the same task with different wording and compare the results.
5. **Share successful use cases.** Tell your team what worked, and save the prompts you would use again.

## Common Mistakes

| Mistake | What to do instead |
| --- | --- |
| Asking a vague question and accepting the first answer | Give context, then ask for improvements |
| Treating the answer as fact | Check anything that matters against a trusted source |
| Pasting in confidential information | Remove sensitive details, or use a tool approved for them |
| Sending the output without reading all of it | Read it through, every time |
| Giving up after one poor result | Reword the request and try again |
